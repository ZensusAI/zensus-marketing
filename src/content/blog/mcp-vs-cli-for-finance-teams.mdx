<p id="blog-article-lead" className="text-lg leading-relaxed text-muted-foreground">I will be honest with you. When our finance leader first asked, "Should we let our AI assistant talk to our accounting system?" my stomach dropped.</p>

<p>We spent months convincing clients that AI could summarize spreadsheets and spot trends. But actually connecting it to their accounting software felt like handing a stranger the keys to their safe.</p>

<p>Then we stumbled on two options: Model Context Protocol (MCP) and CLI, which is what the command-line interface is called.</p>

<p>The difference is not as techy as you might expect. Here is what we learned while we worked through this with real finance teams.</p>

## The Short Answer: What Are We Really Choosing Between?

<p>MCP is like having a well-trained assistant who knows exactly which buttons to press, and they can only press buttons you have already vetted and authorized.</p>

<p>CLI is like giving a trusted team member access to run specific programs. They execute commands you have written, but there is no conversation involved, just the script running in the background.</p>

<p>The key distinction is that MCP is built for AI to discover what it can do. CLI is for running things you have already defined.</p>

### When We Would Say: Go MCP

<p>Your finance team wants AI to answer questions like "What is our cash balance?" or "Which invoices are due this week?" The AI is part of a chat interface, not just background scripts. You can control what the AI can access, without worrying about how it gets there.</p>

### When We Would Say: Go CLI

<p>You need reports that run the same way every Monday, no matter who is using them. You are moving large batches of files around, or doing heavy calculations. The task is dumb repetition. You just execute step 1, then step 2, no thinking required.</p>

### Often, You Will Use Both

<p>Here is what typically works for us. The AI uses MCP to pull financial data. A controlled CLI script validates that data. Then maybe another tool calculates the forecast. A human approves before anything gets posted.</p>

<p>Separating these concerns matters. If the AI can retrieve the data but not change it, you have already won half the battle.</p>

## MCP: The AI Chatbot Way

<p><a href="https://modelcontextprotocol.io" className="font-medium text-primary underline-offset-4 hover:underline">Model Context Protocol</a> is that new protocol in AI circles. Think of it as the plumbing that connects AI assistants to the tools they need.</p>

### How It Works (Actually)

<p>You have three things. First, an MCP host, which is the AI assistant itself. Second, an MCP client, which is the connector inside the assistant that talks to the server. Third, an MCP server, which is your accounting software wrapped to talk to AI.</p>

<p>Real world example: our finance manager asked, "What is our current cash and what invoices are due this week?"</p>

<p className="mb-2 font-medium text-foreground">The AI did not just magically know. It actually called two pre-approved functions through the MCP server:</p>

<ul>
  <li>Get cash balance, you tell it which client and date</li>
  <li>Get outstanding invoices</li>
</ul>

<p>The MCP server translated the ask into the function calls that the accounting system understood.</p>

<p>Crucial point: the accounting system did not change because of this. The system said, "Sure, this user can read that," and the MCP server respected that. The protocol did not grant new permissions. It just facilitated what was already allowed.</p>

### What is Available?

<p className="mb-2 font-medium text-foreground">We have been seeing this applied in some accounting software:</p>

<ul>
  <li><a href="https://learn.microsoft.com/en-us/dynamics365/fin-ops-core/dev-itpro/copilot/copilot-mcp" className="font-medium text-primary underline-offset-4 hover:underline">Microsoft Dynamics 365 has an MCP server</a> that lets AI talk to the ERP. The ERP's existing permissions stay intact.</li>
  <li>QuickBooks has an <a href="https://quickbooks.intuit.com/r/product-update/quickbooks-google-gemini-mcp-connector/" className="font-medium text-primary underline-offset-4 hover:underline">MCP connector for Google's Gemini</a></li>
</ul>

<p>These show it is possible. But hear us out. An MCP integration that can read your balance sheet does not automatically mean it can post journal entries or make payments.</p>

<p>Important: MCP makes the tools available to AI. It does not magically make every possible accounting operation safe for AI to execute.</p>

## CLI: The Just Do It Way

<p>A command-line interface is what it sounds like. You type commands, the system runs them.</p>

<p>You could write a script that does the following. First, it dumps transactions from the accounting system. Second, it checks them for obvious errors. Third, it calculates cash movements. Fourth, it saves the results.</p>

<p>And you could run that script every Monday, regardless of who is the finance person that week.</p>

### The Risk

<p>Here is the tricky part. If you make that script accessible to an AI agent with shell access, you have handed it a nuclear weapon. If that AI ever gets confused and decides to, "Hey, let me check some other directory," boom.</p>

<p>Our advice: only give AI permission to run specific, approved commands. Not full shell access.</p>

### When CLI Shines

<ul>
  <li>Scheduled reports, think of "email me a receivables aging every day at 8 AM"</li>
  <li>Data validation, check for missing fields, invalid dates, duplicates</li>
  <li>Forecast calculations, the math part, not the decision-making</li>
</ul>

<p>The last point is big. Yes, you can theoretically have an AI run your forecast script. But why would you? If the same calculation needs to run every week, write a script and forget about it.</p>

### The Trade-offs

<p>MCP means setting up a server, a client, connections, auth, all that config. Once you have done it right, multiple AI assistants can use it, which is nice.</p>

<p>CLI means you need the command installed, the right environment, and credentials set up. For a single task, that is fine. But if you are managing 50 different scripts, you will wonder if they are all working.</p>

<p>Bottom line: neither architecture is inherently more secure or wrong. The security is in how you deploy it.</p>

## Case Study: A CFO's Weekly Cash Report

<p>We worked with a fractional CFO managing eight client companies. Every Monday morning, they needed to know: Where is the cash? What is coming in? What is going out? What does the cash position look like over the next <a href="/blog/what-is-a-13-week-cash-flow-forecast" className="font-medium text-primary underline-offset-4 hover:underline">13 weeks</a>? Which weeks might fall below their <a href="/blog/cash-flow-early-warning-system" className="font-medium text-primary underline-offset-4 hover:underline">minimum operating cash</a>?</p>

### Option 1: MCP Flow

<p>The CFO asks their AI assistant: "Give me a preliminary 13-week cash flow for Client A, using current cash, open invoices, payroll, and accounts payable."</p>

<p className="mb-2 font-medium text-foreground">The assistant then calls these MCP tools. This is hypothetical.</p>

<ul>
  <li>get_cash_balance, you tell it which client and date</li>
  <li>get_open_receivables, entity is client_a</li>
  <li>get_open_payables, entity is client_a</li>
  <li>get_payroll_schedule, entity is client_a</li>
</ul>

<p>The AI gets the data, passes it to a forecasting engine, and produces a draft report.</p>

<p>Important: this example is illustrative. We do not know if these exact tool names exist in QuickBooks or Dynamics or anywhere. The point is the workflow, not the specific commands.</p>

### Option 2: CLI Flow

<p>Same outcome, different path.</p>

<p>A cron job runs at 8 AM every Monday.</p>

```bash
python validate_exports.py --client client_a
python generate_cash_forecast.py --client client_a --weeks 13
python send_email_report.py --client client_a
```

<p>No AI involved in the calculation. Just scripts doing what they are told.</p>

### Which Should You Pick?

<p>Honestly? Neither makes a forecast more accurate.</p>

<p>Both approaches can work with bad data. The AI in either one can hallucinate or misinterpret something.</p>

<p className="mb-2 font-medium text-foreground">What actually matters:</p>

<ul>
  <li>Is the beginning cash number from the right accounts and right date?</li>
  <li>Are <a href="/blog/predictive-cash-flow-forecasting" className="font-medium text-primary underline-offset-4 hover:underline">expected collection dates</a> realistic or are you using invoice dates?</li>
  <li>Have you included all the payments due, payroll, taxes, debt, whatever?</li>
  <li>Have you avoided double-counting transactions?</li>
  <li>Is the forecast clear about what is data versus assumptions?</li>
</ul>

<p>The interface, whether MCP or CLI, is secondary to the quality of the data and the rigor of the methodology.</p>

## Security: The Real Question

<p>Which is more secure, MCP or CLI?</p>

<p>That is the wrong question.</p>

<p>The right question is who can this AI agent access, what can it change, and how do we stop it from doing things it should not?</p>

### Microsoft's ERP Integration Says This

<p><a href="https://learn.microsoft.com/en-us/dynamics365/fin-ops-core/dev-itpro/copilot/copilot-mcp" className="font-medium text-primary underline-offset-4 hover:underline">Microsoft's documentation on their Dynamics 365 MCP</a> is clear. The MCP server acts on behalf of an authenticated user. If the user in the ERP can read something, the MCP lets the AI read that same thing. If the user cannot, the AI cannot.</p>

<p>The ERP's existing security controls apply. MCP does not replace the ERP's permissions. Apart from a list of approved AI clients, it uses what is already there.</p>

### What You Should Control

<p>Regardless of whether you are using MCP or CLI, think through this.</p>

#### 1. Least Privilege

<p>An AI assistant that helps answer questions does not need to be able to post journal entries.</p>

<p>Start with read-only. Only open up permissions when you have to.</p>

#### 2. Separate Read From Write

<p>An AI retrieving data is not the same as an AI executing a payment.</p>

#### 3. Keep Your Secrets Out of Sight

<p>API keys, tokens, OAuth credentials. Put them in a secrets manager, not in your chat prompts or GitHub repos.</p>

<p>Rotate them, revoke them when no longer needed. Treat them like cash.</p>

#### 4. Client Isolation

<p>If you are a fractional CFO managing multiple clients, your AI should not accidentally be looking at Client B's transactions while helping with Client A's forecast.</p>

<p>The system needs to enforce that boundary. A user saying, "Oh, use Client A's data," does not mean Client B cannot slip in if the system does not check.</p>

#### 5. Keep a Trail

<p>You need to know: Who asked for what? What data came from where? What changed and who approved it?</p>

<p>Whether that is through MCP logs or traditional audit trails, make sure something records it.</p>

## Where MCP Makes Sense for Finance

#### Conversational Finance Questions

<p>"Why did expenses go up last month?"</p>

<p>An AI with properly scoped access can pull the reports, break it down, and say, "Here is what stands out and here is why we think it happened."</p>

#### AI-Assisted Reporting

<p>Instead of manually downloading reports from three different systems, pasting them into a dashboard, and trying to reconcile discrepancies, you can just tell the AI, "Give me the Q3 expense summary across all clients," and it can fetch and compile what is authorized.</p>

#### ERP Integrations

<p>If your ERP or <a href="/blog/can-quickbooks-forecast-cash-flow" className="font-medium text-primary underline-offset-4 hover:underline">accounting software</a> has an MCP server, you can have AI clients talk to it. The catch: does that server expose the tools you actually need? And are those tools safe for AI to use?</p>

## Where CLI Scripts Are Better

#### Repetitive Reporting

<p>"Show me the receivables aging" does not change week to week. A script that pulls the data, processes it, and emails the report is rock-solid and needs little oversight.</p>

#### Data Validation

<p>Find missing fields, weird dates, duplicate transaction IDs. These are problems that are easier to catch when the validation logic is explicit and repeatable.</p>

#### Forecasting Calculations

<p>Once you have validated inputs, a deterministic engine can <a href="/blog/how-to-build-a-13-week-cash-flow-forecast-in-excel" className="font-medium text-primary underline-offset-4 hover:underline">calculate the cash projection</a>. Whether that engine is called by an MCP tool, a CLI script, or a web app should not matter.</p>

#### Batch Processing

<p>Eight clients, 12 periods, all the same report. A controlled job runner will handle this more reliably than an AI trying to figure out each one.</p>

## The Hybrid Approach (Our Recommendation)

<p>We have found that for most finance teams, the winner is a hybrid.</p>

### Here is a workflow that worked for us

<ul>
  <li>AI, via MCP, pulls the financial data. The user asks a question, the AI retrieves what it is allowed to access.</li>
  <li>Controlled validation, through CLI or similar, checks the data for completeness, format, obvious errors.</li>
  <li>Deterministic calculation runs the forecast using the validated inputs.</li>
  <li>AI summarizes potential issues or exceptions.</li>
  <li>Human approves before anything gets posted.</li>
</ul>

<p>This gives you the best of both worlds. The conversational flexibility of AI, without letting the AI be responsible for calculations or approvals.</p>

## Before You Connect AI to Finance Systems

<p className="mb-2 font-medium text-foreground">Run through these questions with your finance and IT leaders:</p>

<ul>
  <li>Identity: Can we tell exactly which user or service account made each request?</li>
  <li>Permissions: Does this integration follow least privilege?</li>
  <li>Read versus Write: Are reporting functions separate from functions that change data?</li>
  <li>Approvals: Do high-risk actions require human authorization?</li>
  <li>Secrets: Are API keys stored securely, not in prompts or code?</li>
  <li>Client isolation: Can we guarantee Client A's data stays with Client A?</li>
  <li>Audit logs: Can we reconstruct what happened if something goes wrong?</li>
  <li>Data quality: Are we validating inputs and checking outputs?</li>
  <li>Failure handling: What happens if permissions break or the API changes?</li>
  <li>Offboarding: Can we revoke access quickly when someone leaves?</li>
</ul>

<p>These controls apply whether you are using MCP, CLI, or a traditional API integration.</p>

## The Bottom Line

<p>This is not about MCP being new and shiny or CLI being old and clunky.</p>

<p className="mb-2 font-medium text-foreground">It is about designing workflows where:</p>

<ul>
  <li>The AI can access the information it needs, when authorized</li>
  <li>The calculations are performed by something reliable</li>
  <li>A human reviews before anything affects accounting records</li>
  <li>You have an audit trail you can trust</li>
</ul>

<p>For finance teams, that is what makes AI-enabled workflows actually useful.</p>
